# 05 - Receiver Setup, Start and Restart

---

## Install the virtual gamepad driver (once)

The receiver turns the controller into an Xbox 360 controller using ViGEmBus.

1. Run `ViGEmBus_1.22.0_x64_x86_arm64.exe` as administrator.
2. Accept the UAC prompt and complete the installer.
3. Reboot if asked.

Without this driver the receiver exits at startup with a clear error message.

---

## Files you will use

| File | When |
|---|---|
| `start-receiver.vbs` | Start the receiver manually |
| `restart-receiver.vbs` | Kill the old process and start fresh |
| `autostart-receiver.vbs` | Copy into Startup folder to run at logon |

All three are generated by `configurator.html` with your actual IP addresses and paths.
They run hidden, with no console window.

---

## Start the receiver

Double-click `start-receiver.vbs`. A popup confirms it started.

The equivalent command line is:

```
stadiacast.exe --preset live --advertise-ip <pc-ip> --controller-ip <controller-ip> \
  --dns-upstream <router-ip> \
  --dns-redirect "time.google.com,clients3.google.com,clients4.google.com,connectivitycheck.gstatic.com,connectivitycheck.tencent.com,www.google.com" \
  --gamepad vigem --audio-source system \
  --log-dir "<project>\logs\autostart"
```

Why these flags matter:

| Flag | Reason |
|---|---|
| `--preset live` | Proven flag set. Includes clearcut blocking; without it the controller powers off after seconds. |
| `--gamepad vigem` | Creates the virtual Xbox 360 controller. |
| `--advertise-ip` | Your PC's address written into ICE candidates and DNS answers. |
| `--controller-ip` | The controller's address, used by the DNS/SNTP helpers. |
| `--dns-redirect` | The Google endpoints intercepted for the controller. |
| `--audio-source system` | Optional. Streams PC audio to the headset jack. |

Do not remove `--preset live`.

## Connect the controller

Short-press the Stadia button (about 1 second, release at the first rumble).

- **Two short rumbles + steady white light** = connected.
- **Blinking light with no rumble** = the controller only reported a wake; press again.
- First boot after pairing often registers only. Wait about a minute, power off with a
  long press, then wake again.

Check in Windows:

- `joy.cpl` shows an Xbox 360 Controller.
- `http://<pc-ip>/_status` shows the controller with session state `dtls-connected`.
- The log shows `gamepad_created`.

## Restart the receiver

Double-click `restart-receiver.vbs`. It:

1. Terminates every `stadiacast.exe` process.
2. Waits 2.5 seconds for ports to free.
3. Starts a fresh receiver with the same configuration.
4. Prompts you to press the Stadia button again.

Use this after changing settings, after updating files, or whenever the receiver seems stuck.
You must wake the controller again after a restart.

---

## Autostart at logon

Copy `autostart-receiver.vbs` into your Windows Startup folder:

```
C:\Users\<you>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
```

It is silent and includes a guard: if a receiver is already running, it exits without
starting a duplicate.

---

## About the helper processes

A running receiver appears as four `stadiacast.exe` processes:

- One parent / launcher
- One main server (listens on TCP 443)
- One `dns_sink` helper (UDP 53)
- One `sntp_server` helper (UDP 123)

This is normal. Do not try to kill them individually.

On Windows, the SNTP helper may print an error because the `w32time` service already
uses UDP 123. **This is harmless** - the controller takes its time from HTTP Date
headers, and a full working session has been observed with zero SNTP queries.

---

## Ports used

- TCP 443, 80, 8008
- UDP 53, 123, 40000, 40001

If your firewall is enabled, allow these. Many home setups simply disable the firewall
for the private network profile.
